\section{Measuring Phrase Recognition}
\label{sec:method}

\begin{figure*}[t]
\centering
\includegraphics[width=\textwidth]{figures/protocol}
\caption{The protocol. We interrupt the model inside a known phrase, leaving $i$
tokens unread, and ask whether those tokens are recoverable from that point by
two different means: injecting the hidden state into an unrelated prompt
(Patchscopes), or letting the model continue from the prefix it has actually
seen (generation). Both are scored identically. In both, only the first token is

\label{fig:protocol}
\end{figure*}

We now describe how we measure whether the rest of a phrase can be recovered
partway through it. We first define where we interrupt the model and how far
ahead we ask it to look. We then describe the two measurements we take at that
point: reading the hidden state with Patchscopes, which is our main analysis,
and letting the model continue on its own, which shows what it actually does.
Finally we give the rule that decides whether a trial succeeded.
Figure~\ref{fig:protocol} summarises the protocol.

\subsection{Lookahead distance}

Let a phrase tokenize as $t_1 \ldots t_n$. We interrupt the model at position
$p$ and define the \emph{lookahead distance} $i = n - p$ as the number of
phrase tokens that remain unread. The target is the decoded string of those $i$
tokens. A single phrase therefore yields several trials, one per position, and
$i$ is the difficulty axis throughout: larger $i$ means the model must account
for more unseen material.

Every phrase is processed with its full left context (a BOS token, then, where
applicable, the natural text preceding the phrase), so the state at position
$p$ is the state the model would actually have at that point. We analyse $i
\geq 2$ throughout; $i=1$ reduces to ordinary next-token prediction and is not
of interest here.

\subsection{Two measurements}
\label{sec:measures}

We ask whether the remaining tokens are recoverable from the model at position
$p$ in two ways. Both start from the same interrupted input and differ in what
they take from it.

\paragraph{Patchscopes.}
Following \citet{ghandeharioun-etal-2024-patchscopes}, and ultimately the causal
intervention of \citet{pal-etal-2023-future}, we take the hidden state
$h^{\ell}_p$ at layer $\ell$ and position $p$, and substitute it for the token
embedding of \texttt{X} in the prompt \texttt{"Repeat this: X"}. We then decode
greedily for $i+3$ tokens. Patchscopes succeeds at layer $\ell$ if the target
string occurs in the output, case-insensitively. Unless stated otherwise we
report the union over layers: it succeeds if \emph{any} probed layer
succeeds. This is deliberately generous, and \S\ref{sec:disagreement} shows how
much the number of layers in the union changes the result.

\paragraph{Generation.}
We take the same prefix, context plus the first $p$ phrase tokens, and let
the model generate greedily for $i+3$ tokens, with no intervention of any kind.
Success is judged by the same string-containment criterion.

The two answer different questions. Patchscopes tests whether the target phrase
can be recovered from a single hidden state, and it is our main tool for
looking inside the model. Generation records what the model actually does under
greedy decoding: whether it goes on to produce the phrase. We treat it as
ground truth for the model's behaviour in that setting, not as another way of
reading the state. The two are not interchangeable: \S\ref{sec:disagreement}
shows cases where Patchscopes recovers a phrase the model does not go on to
produce.

Both measurements decode one token at a time, so recovering a target of several
tokens does not show that each of those tokens is separately encoded in the
state at the cut: after the first generated token, the rest may follow from
what has already been emitted. What a success shows is that the state carries
enough information to bring the continuation out. We use \emph{recognition} in
this practical sense throughout: a phrase is recognized at distance $i$ when
the measurement in question recovers its remaining $i$ tokens under the
matching rule below.

\subsection{Success criterion}
\label{sec:criterion}

A trial succeeds if the target string appears as a case-insensitive substring
of the generated continuation. The budget of $i+3$ tokens allows the model to
overshoot slightly (a trailing clause after the phrase does not cost it the
trial) while staying tight enough that a success reflects the phrase rather
than a long ramble that happens to contain it.

The criterion is lenient in one direction and strict in the other. Lenient,
because it accepts any output containing the target without asking whether the
model produced it for the right reason; strict, because it demands the exact
wording: \textit{he who laughs last laughs \underline{best}} scores as a
failure against \textit{laughs loudest}, though it is the more common form.
\S\ref{sec:falsepos} quantifies how often that strictness misclassifies a
correct completion.
