\section{Experimental Details and Supporting Analyses}
\label{app:details}

\subsection{Implementation}

Hidden states are extracted with a single forward pass over \texttt{[BOS]} $+$
context $+$ phrase, with \texttt{output\_hidden\_states} enabled. The BOS token
matters here: a phrase's first token has a different state at position $0$ than
at position $1$ after a BOS, so we always include it. Positions are enumerated
from the first phrase token to the second-to-last; the BOS and the final phrase
token are never cut points.

For Patchscopes, the states for all probed layers are stacked into
one batch and decoded in a single \texttt{generate} call. This is one call, not
one sequence's worth of computation: the sweep still decodes one sequence per
layer. Decoding is greedy
throughout, for both measurements, with \texttt{max\_new\_tokens} $= i+3$.

\subsection{Scoring at the token level}

The target is the decoded string of the final $i$ tokens, which for some
phrases begins mid-word: at $i=2$ in \textit{Sistine Chapel} the target is
\textit{istine Chapel}, and in \textit{Pulp Fiction} it is \textit{ulp
Fiction}. The criterion is applied identically to both measurements, so
comparisons between them are unaffected, but absolute rates for phrases with
unusual tokenization are not directly interpretable as ``the model produced the
phrase''. Rerunning with word-aligned cut points would make the absolute
numbers cleaner.

\subsection{Patchscope prompt ablation}

The prompt \texttt{"Repeat this: X"} offers one slot for the injected state.
Because the target is several tokens long, a natural worry is that one slot is
too little room. We reran the isolated-phrase sweep with
\texttt{"Repeat this: X X X X X"}, injecting the same state into five slots.
It does not help, and at longer distances it hurts: $27.4\%$ versus $30.9\%$ at
$i=3$, $15.8\%$ versus $19.4\%$ at $i=4$, and $12.4\%$ versus $16.5\%$ at
$i=5$. We therefore use the single-slot prompt throughout. The failure mode at
long $i$ is not a shortage of output positions.

\subsection{Probe configuration}

Both probes use an MLP with a single hidden layer of $32$ units, trained on the
standardised hidden state at the cut position. Data are pooled over $i \in
\{2,3,4,5\}$ and split $80/20$ with \texttt{GroupShuffleSplit} grouped by
phrase, so no phrase appears in both partitions; the majority class is
downsampled in the training set only, and the test set is left at its natural
distribution. All reported runs use seed $42$. The false-positive and
confidence analyses of \S\ref{sec:falsepos} use the L25 probe.

\subsection{The Patchscopes label at the earliest layers}

Patchscopes itself almost never succeeds in the first few layers ($0.6\%$,
$0.8\%$ and $1.5\%$ at L0, L1 and L2), so a probe trained on that label there
has a positive class of about $1\%$ of the data and one split can swing on
luck. Balanced accuracy is nonetheless well above chance at those depths:
$72.2\%$ at L0, $74.7\%$ at L1 and $68.9\%$ at L2. We report these as unstable
rather than as a finding; no multi-seed check was run.

\subsection{False-positive adjudication prompt}
\label{app:judge}

The $212$ false positives of \S\ref{sec:falsepos} were adjudicated by
presenting them to ChatGPT (GPT-5.6 Sol) in a single batch. The prompt was
(reproduced verbatim, including its punctuation):

\begin{quote}\small
I have 212 cases where a language model was supposed to complete a phrase (a
well-known idiom, movie title, or landmark name) but its actual output didn't
exactly match the target string. For each one, I have the target (the correct
completion) and what the model actually generated. I want you to classify each
case into exactly one of three categories:

\textbf{Valid alternate}: the model's answer means the same thing or is a
genuinely acceptable variant (a synonym, a common alternate phrasing of the same
idiom, a spelling variant, a grammatically different but equivalent form, or a
very reasonable related answer like a sequel number).

\textbf{Partially right}: the model got some of it right but changed or
dropped something meaningful, so it's not quite equivalent but clearly shows
real knowledge of the target.

\textbf{Unrelated}: the model's output has no real connection to the target;
it looks like genuine confusion.

For each of the 212 lines below, respond with just the number and the category
(e.g., ``1. Valid alternate''). At the end, give me a total count and percentage
for each of the three categories.
\end{quote}

Each case was supplied on one line as
\texttt{N. PHRASE: <phrase> | TARGET: <target> | GENERATED: <generated text>}.
The rubric wording, in particular the instruction that a variant counts as
valid, plainly invites a generous reading; the resulting split should be taken
as an upper bound on how many of these are acceptable rather than mistakes.

\subsection{An efficiency pilot}

Separately from this paper we reproduced CLP \citep{xie-zhou-2026-clp}, a
learned linear read of the hidden state that sets how many drafted tokens to
accept at each step, on Qwen3.5-2B. It reached roughly $1.34\times$ the
throughput of plain autoregressive decoding; a fixed-length policy was faster
still, at $1.72\times$. The test set contained only ten held-out prompts, so
the result is inconclusive.

Three caveats. Our figure exceeds the $1.14\times$--$1.29\times$ Xie and Zhou
report, which we take to reflect differences in model, hardware and workload
rather than a better implementation. Divergences from autoregressive output
appeared under \emph{every} policy we tried, including fixed-length ones with
no adaptive logic, pointing at this model's interaction with the inference
engine rather than at any policy. They were also more common for the aggressive
fixed-length policies (six of ten prompts against two for CLP), so the
additional speed comes with a higher divergence rate. We report the pilot only
because it bounds how much the lookahead we measure might be worth in practice.

\subsection{Reproducing the numbers}

All main-text numbers except Table~\ref{tab:probes} and the adjudication in
\S\ref{sec:falsepos} are regenerated from \texttt{results/raw/} by scripts
under \texttt{code/}: one writes a processed JSON file, which the table and
figure scripts then consume. The experiment scripts that produced the raw
results sit alongside them. The repository README gives the exact filenames and
the commands to run them.

Two results are not regenerated from this repository. The probing experiments
need per-trial hidden states, $1.28$\,GB for the Patchscopes labels and
$3.02$\,GB for the generation labels. These are too large to distribute and
remain on the compute cluster, so the probe numbers in Table~\ref{tab:probes}
are reported from the run logs rather than recomputed from this repository. The
false-positive adjudication of \S\ref{sec:falsepos} rests on a single judge
with no human validation and no inter-annotator agreement; the judge and prompt
are named in this appendix, so the run can be repeated, but a single automatic
judge is not a substitute for human annotation. The confidence-based split in
\S\ref{sec:falsepos} uses no judge and points the same way.
